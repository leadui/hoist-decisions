The problem

One line of diff.
Weeks to undo.

Your agent picks a database, an auth scheme, a hosting platform — mid-task, mid-diff, with no pause. Switching later means a migration, a rewrite, or living with it. educated decisions need a moment; Hoist makes that moment.

WITHOUT HOIST

The agent guesses, you discover

npm install mongoose lands in a diff at 2am. Nobody chose MongoDB — it simply happened. Six months later the schema fights you on every feature.

WITH HOIST

The agent pauses, you decide

The hook notices what changed, not what was typed. The agent waits. You get a decision moment: each option expanded, trade-offs charted, then one commit sends your agent back with your choice.

The decision moment

Five steps. Ninety seconds. Zero regrets.

From interruption to committed record, the whole loop is built to educate first and decide second.

01 · EXPAND

Every option opens inline

Tap any option for its full deep dive: the story in plain words, the step-by-step journey, concrete numbers, unlocks and watch-outs, and a growth chart that shows the future you are signing. Lean drafts stream in parallel, so the first moment is interactive in seconds — deep numbers pull lazily, only when you open them.

02 · HYPER-DIVE

The full screen, one option

Still unsure? The hyper-dive lays everything flat — story, mechanics, numbers, docs, web search — with the option number pinned up top.

03 · INTERRUPT

Paused, not blocked

The hook catches lasting choices from tool calls. Quick-pick here, or walk through it.

04 · COMMIT

One tap back to chat

Review the set, commit, and your agent resumes with your choices.

05 · GUARD

Records that bite

Later conflicts get blocked with a citation to the record you committed.

Decision records

Decisions you can grep.

Every committed moment lands in docs/decisions/ as a MADR record — readable on GitHub, readable by your next agent, checkable by the hook.

---
status: accepted  date: 2026-10-28  door: one-way
deciders: project owner  confidence: medium
---
# Choose persistence for users and projects: SQLite on the server

> Decision: SQLite on the server. Because it stays boring
  while the project grows. Accepted cost: a migration if you
  outgrow one machine.

## Decision Drivers
- Must survive restarts and concurrent saves (the task)
- No ops team to babysit a server (assumed, not checked)

### Confirmation
- [ ] Confirm the hosting disk persists across deploys
- Hoist flags later changes that conflict with this record.

Install

Guarding your repo in one command.

Python 3.9+, Muse Code, zero dependencies. The decision page runs on your machine and makes no API calls.

$git clone git@github.com:leadui/hoist-decisions.git


$python3 hoist-decisions/hoist.py install /path/to/your/project


$python3 hoist.py serve   # browse moments at http://127.0.0.1:7317
