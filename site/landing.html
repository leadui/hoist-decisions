02 · The problem

One line of diff.
Weeks to undo.

Muse picks a database, an auth scheme, a hosting platform — mid-task, mid-diff, no pause. Switching later means a migration, a rewrite, or living with it. Big calls deserve a moment; Hoist makes that moment.

WITHOUT HOIST

The agent guesses, you discover

Muse drops npm install mongoose into a diff at 2am. Nobody chose MongoDB — it simply happened. Six months later the schema fights you on every feature.

WITH HOIST

The agent pauses, you decide

Muse asks instead: answer here, or decide with Hoist. Pick Hoist and the session pauses — you get a decision moment with every option expanded and charted, then one commit sends Muse back with your choice.

# Choose persistence for users and projects: SQLite on the server

> Decision: SQLite on the server. Because it stays boring
  while the project grows. Accepted cost: a migration if you
  outgrow one machine.

## Decision Drivers
- Must survive restarts and concurrent saves (the task)
- No ops team to babysit a server (assumed, not checked)

### Confirmation
- [ ] Confirm the hosting disk persists across deploys
- Hoist flags later changes that conflict with this record.
accepted · 2026-10-27 · door: heavy · 0001-interrupt-muse-code-routing-question.md

Routing question first, caught in PostToolBatch

Because it is the only path proven live: hooks can't see the questionnaire, but PostToolBatch receives its answers.

CONTEXT

Muse Code asks lasting questions in its own questionnaire with expert labels. Hoist takes over that moment and brings the decision back into the flow.

DRIVERS
  • Interrupt at ask-time, not at install-time
  • The pick must reach the agent unprompted
  • A Hoist pick ends the form at once
CONSIDERED OPTIONS
  1. Routing question + PostToolBatch
  2. Inject the option via PreToolUse
  3. Replace the questionnaire early
  4. A session from every prompt
CONSEQUENCES
  • Deterministic catch from logged answers
  • Full session, not bare options
  • Depends on the agent following the skill
  • Wait lives in a 5-minute window
accepted · 2026-10-28 · door: one-way · 0002-sqlite-persistence.md

SQLite on the server

Because it stays boring while the project grows. Accepted cost: a migration if you outgrow one machine.

CONTEXT

Users and saved projects must survive restarts and concurrent saves, and there is no ops team to babysit a database server.

DRIVERS
  • Survive restarts, concurrent saves
  • Zero babysitting
  • Revisit only when scale demands it
CONSIDERED OPTIONS
  1. SQLite on the server
  2. Postgres + Prisma
  3. Mongo + Mongoose
CONSEQUENCES
  • Zero ops, one file to back up
  • Fast enough until proven otherwise
  • Single writer, one machine
  • Migration day comes eventually
accepted · 2026-10-28 · door: heavy · 0003-authjs-sessions.md

Auth.js + Postgres sessions

Because it is an open standard with magic links and zero per-user cost. Accepted cost: about a day to wire up.

CONTEXT

A 3-person team needs login this week; hosted auth pricing stings later, and rolling your own owns every breach.

DRIVERS
  • Ship login in about a day
  • No per-seat tax
  • Own the sessions table
CONSIDERED OPTIONS
  1. Clerk
  2. Auth.js + Postgres
  3. Roll your own
CONSEQUENCES
  • $0/mo, standard flows
  • Magic links included
  • A day to wire providers
  • You own the session config

05 · Install

Guarding your repo in one command.

Python 3.9+, Muse Code, zero dependencies. The page serves from your machine while Muse drafts every moment over the API.

$git clone git@github.com:leadui/hoist-decisions.git


$python3 hoist-decisions/hoist.py install /path/to/your/project


$python3 hoist.py serve   # browse moments at http://127.0.0.1:7317
